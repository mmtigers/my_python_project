# Family Quest ラズパイデプロイ前 動作検証手順

Family Quest はラズパイ上で稼働させる前提のシステムだが、以下の手順に沿えば
ロジックの大部分は PC（ラズパイ以外の環境）で事前検証できる。

構成は以下の2階層。

- **バックエンド**: `MY_HOME_SYSTEM`（Python / FastAPI / SQLite）
- **フロントエンド**: `family-quest`（React / TypeScript / Vite）

---

## ① バックエンド (MY_HOME_SYSTEM) セットアップ

```bash
cd MY_HOME_SYSTEM
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env          # 必要な値を編集
```

## ② 自動テスト・静的解析

```bash
pytest                        # tests/ 配下35本超。DBは一時SQLiteに自動分離される
ruff check .                  # Lint
bandit -r .                   # セキュリティ静的解析
pip-audit                     # 依存脆弱性チェック
```

## ③ DB初期化 & バックエンド単体起動

```bash
python3 init_unified_db.py    # ローカルにSQLite DBを作成
python3 unified_server.py     # サーバー起動（ハードウェア非依存のAPIはこれで動く）
```

→ curl/ブラウザで `quest_router` 等のAPIを叩いて手動確認。

## ④ フロントエンド (family-quest) セットアップ・確認

```bash
cd ../family-quest
npm install
npm run lint
npm run dev                   # Vite開発サーバーでUI動作確認（バックエンドAPIをlocalhostに向ける）
npm run build                 # tsc -b && vite build で型チェック込みビルド確認
```

## ⑤ 統合確認（本番構成の再現）

```bash
# ③のビルド成果物を使い、.env の QUEST_DIST_DIR を family-quest/dist に設定
cd ../MY_HOME_SYSTEM
python3 unified_server.py     # フロント込みでラズパイと同じ配信構成をPC上で確認
```

## ⑥ 実機依存部分は割り切って確認

SwitchBot / Nature Remo / カメラ監視 / NASマウント(`/mnt/nas`) はモックがないため、
ここまでの手順ではエラーになるだけ。この部分だけはラズパイ実機に持って行った後、
`start_all.sh` 実行時のログ(`logs/`配下)で最終確認する。

---

## まとめ表

| 対象 | ラズパイ不要で検証可能 | 実機必須 |
|---|---|---|
| クエスト/レベル/DBロジック | ✅ pytest で網羅的に可能 | - |
| API・SPA配信の統合動作 | ✅ ローカルで再現可能 | - |
| SwitchBot/Nature Remo/カメラ/NASマウント | △ 起動はできてもエラーになる | ✅ 実機接続確認が必要 |

上記①〜⑤がすべて通ってから、ラズパイへ `git pull` ＋ `start_all.sh` でデプロイする。

## ⑦ Windows(PowerShell)での動作検証

### 初回セットアップ時の注意点(Pythonバージョン)

- **Python 3.12系を使うこと**。3.10だと `contourpy` 等の一部依存が入らず、3.14(最新)だと
  `numpy` 等のビルド済みwheelがまだ無く、ソースビルドしようとしてC11対応コンパイラ不足で失敗する。
- 複数バージョンが入っている場合は `py -3.12 -m venv .venv` のように明示的にバージョンを指定してvenvを作成する。
- PowerShellでのvenv有効化は `source .venv/bin/activate` ではなく `.venv\Scripts\Activate.ps1`。
  実行ポリシーで弾かれる場合は該当ウィンドウ限定で
  `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` を先に実行する。
- 初回起動時、DBが空だとフロント画面(家族選択・クエスト一覧)が何も表示されない。
  以下のシードAPIでマスターデータ(`quest_data.py`の内容)を投入すると解消する。
  ```powershell
  curl.exe -X POST http://localhost:8000/api/quest/seed
  ```
  (PowerShellの`curl`は`Invoke-WebRequest`のエイリアスで挙動が違うため`curl.exe`と明示するか、
  `Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/quest/seed` を使う。)

### 2回目以降の起動手順(`.venv`・DBが既にある場合)

**① バックエンド(PowerShellウィンドウ1)**
```powershell
cd MY_HOME_SYSTEM
.venv\Scripts\Activate.ps1
python unified_server.py
```
→ `Uvicorn running on http://0.0.0.0:8000` が出たらそのまま放置。
`camera_monitor.py` の `max_workers must be greater than 0` エラーはハードウェア未接続による
想定内のエラーなので無視してよい(⑥参照)。

**② フロントエンド(PowerShellウィンドウ2、新規で開く)**
```powershell
cd family-quest
npm run dev
```
→ `Local: http://localhost:5173/quest/` が出たらそのまま放置。

**③ ブラウザで確認**
```
http://localhost:5173/quest/
```

前回投入したデータはDBに残っているので、シードAPIの再実行は不要。
終わったら両方のウィンドウで `Ctrl+C` で停止する。
